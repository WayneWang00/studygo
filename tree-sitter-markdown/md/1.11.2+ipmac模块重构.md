## 一、需求分析

### 用户需求

从三层交换机接收syslog日志，并从中提取日志中IP-MAC的信息，并在AC上设置该MAC为该IP的真正MAC，解决跨三层后MAC地址不是真正的客户端MAC的问题。

然而，不同的三层交换机，其syslog日志的格式不一样，所以要根据交换机类型定制IP-MAC的解析方式。

### 系统需求

- 支持UDP任意端口接收syslog

- 支持可扩展性，与多种设备对接

- 快速定制

## 二、现有方案分析

现有的代码包含

- getipmac - 主进程（除了加载插件啥事也没干）

- libmac_down - 一个插件形式的服务端，负责将IP-MAC数据下发到驱动

- libmac_send - 一个插件形式的客户端，负责将IP-MAC发送到libmac_down

- libsyslog_ipmac - 一个接收syslog日志，并调用libmac_send
  API发送消息到libmac_down的插件。

现有方案的问题：

- 绕了一个大弯实现下发驱动

- 没有框架概念，插件各自为政，没有抽像出该有的机制

/\*\* \* 向驱动下发mac列表，为增量下发，驱动自动淘汰超量、过时的条目 \*
\\param items 列表 \* \\param nitem 列表数目 \* \\return
成功返回0，否则失败 \*/int authdrv_down_maclist(const mac_item_st
\*items, size_t nitem);

注：libauthdrvnotify库已经提供了基础函数用于下发mac列表

### 配置方式的分析

现有程序使用配置进行匹配提取，这没什么问题，但处理文本，正则不一定足够，该方案只能保证满足大部分情况，无法保证全部情况，例如mac地址的格式可能为1234.5678.abcd，一条日志也可能包含多个IP和mac。

## 三、重构方案

为了支持可扩展性和可定制性，决定引入lua，而\"think in
lua\"是一个简单有效的提升设计质量（可扩展性，断耦）的手段。

### 从Lua倒推

引入lua，首先应考虑的问题是，lua要怎么写，就像原始的使用配置的方式，首先考虑的就是有什么选项供配置，不同的是考虑完lua要怎么写后，我们的系统分层，模块设计会基本定型。

换位思考，从二次开发程序员出发，我认为应该这样写：

local regex = require \"regex\"local myreg = regex.new(\"syslog REGEX\")

\-- 监听514端口

sys.listen(514, function(str)

\-- 捕获ip/mac

local capture = {}

if myreg:match(str, capture) \>= 0 then

local ip = capture\[1\]

local mac = capture\[2\]

if not ip and not mac then

\-- 提交ip/mac到驱动

sys.commit(ip, mac)

return true

end

end

\-- 返回false表示继续处理下一个插件，允许多个插件在同一端口上监听

return falseend)

从该段二次开发的代码中可以看到很清晰的框架部分：

- sys.listen \-- 用于监听指定端口

- sys.commit \-- 用于提交分析结果

### 是否需要支持C插件

系统中很多程序都同时支持了C和lua插件，与lua插件很类似，如果支持C插件，则sys.listen要有C的实现，为了取得更广泛的支持，我们实现C版本的sys.listen/sys.commit，并导出lua
API

/\*\* \* 监听函数回调，处理syslog \* \\param data 待处理的数据 \*
\\param len 数据长度 \* \\param userdata 用户数据 \* \\return
返回0时表示已经处理，不要再分发给下一个回调 \*/typedef int
(\*sys_data_fn_t)(const char \*data, uint32_t len, void \*userdata);

/\*\* \* 注册监听回调 \* \\param port 端口 \* \\param cb 回调 \* \\param
userdata 传送给cb的用户数据 \* \\return 成功返回0，否则失败 \*/int
sys_listen(uint16_t port, sys_data_fn_t cb, void \*userdata);

/\*\* \* 向驱动提交地址与MAC \* \\param addr IP地址 \* \\param mac
长度为6的MAC地址 \*/void sys_commit(const struct l3_addr_st \*addr,
const uint8_t \*mac);

### 实现清单

- libsysframe.so \--
  实现C的框架库，所有插件链接该库以使用sys_listen和sys_commit

- sysloglistener \-- 主程序

- plugins/libsyslua.so \-- lua的封装，加载和运行lua代码

## 四、总结

从这个例子中，我们提取出了一些机制性的东西成为框架，sys_listen/sys_commit便是其中的代表，处理了数据来源和数据输出，满足了可扩展的需求。

对于文本的处理，则交通过libsyslua插件交给了lua代码，保证了多样的扩展性。

对于一个程序来说，还需要可调试性，可测试性等等，这里不一一编码。
